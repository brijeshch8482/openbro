# OpenBro Memory v2 — Design

Status: **built** (proposed 2026-10-07; built 2026-11-26 as harness pieces 2–3 — see HARNESS.md for the differences). Designed for OpenBro's reality: weak/free models (Groq 8B/70B,
local GGUF), tight token budgets (Groq free-tier TPM), multiple channels
(CLI, Telegram, voice).

---

## 1. Why change

What exists today (see `openbro/memory/`, `openbro/core/agent.py`,
`openbro/brain/memory.py`, `openbro/core/session_memory.py`):

| Piece | Problem |
|---|---|
| `Agent._trim_history` | Cuts by **message count** (50). Can split an `assistant(tool_calls)` from its `tool` results → orphan `tool` message → 400 on strict APIs. Old context is dropped with no summary. |
| `facts` table (key/value) | Only 20 newest facts injected, regardless of relevance. Flat key/value can't hold "why" or "how to apply". Written only when the user says "yaad rakh". |
| `MemoryManager._working` deque | Unused — the agent keeps its own `self.history`. |
| `conversations` table | Stores only user/assistant text. Tool calls are lost, so `--resume` restores a lossy history. Search is `LIKE '%q%'`. |
| `brain/memory.py` (SemanticMemory) + `brain/reflection.py` | Only called from `core/reasoning.py`, which nothing imports. Dead in the chat path. Separate DB file. |
| `session_memory` goals | Regex-detected goals; milestones never recorded. |

## 2. Principles

1. **Plain files, not a vector DB, for memories.** The model retrieves via a compact index; files are human-readable and editable.
2. **Summarise, never blind-truncate.** Cuts happen on turn boundaries.
3. **Three separate concerns:** instructions (human-written), memories (model-written), context (session).

Weak models are worse at "read the index and decide", so the index is
**ranked and budgeted by code** (FTS5, optional embeddings) before
injection. This is context building, not a tool shortcut — tools still do
one thing and return raw data (see the "no tool shortcuts" rule).

## 3. Architecture

```
                 ┌───────────────── system prompt (stable) + per-call reminder ─┐
L0 Instructions  │ OPENBRO.md (global + project)                               │
L1 Memories      │ ranked memory index (budgeted)                              │
                 │ [CONVERSATION_SUMMARY] (from L2, if compacted)              │
                 └─────────────────────────────────────────────────────────────┘
L2 Session ctx   recent turns verbatim  ←─ Compactor (token budget, turn-safe)
L3 Transcripts   SQLite: every message incl. tool calls + FTS5  ──→ resume / search
```

### L0 — Instructions (`openbro/memory/instructions.py`)

- Files, loaded whole, in order:
  1. `<config_dir>/OPENBRO.md` (global, user-written)
  2. From the git root (or cwd) down to cwd: `OPENBRO.md`.
- Hard cap (default 4K tokens total); over-cap files are truncated with a note.
- Cached by mtime; re-read when cwd changes.
- `/memory edit` in the REPL opens the global file in `$EDITOR`/Notepad.

### L1 — Memories (`openbro/memory/notes.py`)

**Storage:** `<storage>/memory/notes/<user_id>/*.md`, one memory per file:

```markdown
---
name: prefers-hinglish-short-replies
description: User wants short Hinglish replies, no tutorial tone
type: feedback            # user | feedback | project | reference
scope: global             # global | project:<repo-root-path>
created: 2026-10-07
updated: 2026-10-07
---
Short Hinglish replies, no step-by-step lectures unless asked.
**Why:** said "tutorial jaisa mat bol" on 2026-06-20.
**How to apply:** default to 1–3 lines; expand only on request.
```

**Index:** `INDEX.md` is **generated by code** from frontmatter (never hand-
or model-edited — a weak model must not be able to corrupt it). One line:
`- [name] (type) — description`.

**Injection (every turn, `MemoryManager.system_block(user_msg)`):**
1. Always include `user` and `feedback` memories (who the user is, how to behave).
2. Include `project` memories whose scope matches the current repo.
3. Fill the remaining budget (default 1.5K tokens) with the best FTS5 matches
   for the current user message, then by recency.
4. If anything was left out, append: `(+N more memories — use memory.search)`.

The bodies of memories are not injected; the model calls `memory.read` when
a line looks relevant. Exception: when total memory is tiny (< budget),
inline bodies too — saves a tool round-trip on weak models.

**Search index:** SQLite FTS5 table `notes_fts(name, description, body)`,
rebuilt incrementally from file mtimes on startup. Optional embeddings ranker
(reuse `SemanticMemory._embed` code) when `sentence-transformers` is
installed — blended with FTS rank, never required.

**Memory tool v2** (`openbro/tools/memory_tool.py`) — raw operations only:

| action | args | returns |
|---|---|---|
| `save` | name, description, type, body, scope? | path written (upserts by name) |
| `read` | name | full file |
| `delete` | name | ok / not found |
| `list` | type? | index lines |
| `search` | query | ranked index lines + top snippets; also hits from L3 transcripts |

**When to save** is taught via a principle in the system prompt: save when the user states something about
themselves, corrects the agent, or a durable project fact/decision appears;
update instead of duplicating; delete what turns out wrong; never save
secrets or what is derivable from the repo.

**Auto-extract (optional, `memory.auto_extract`, default on for cloud
providers, off for local):** on session end (`/exit`, Telegram idle 30 min),
one LLM call gets the session summary + current index and returns proposed
`save/delete` ops as JSON; they are applied through the same `NoteStore` API
and shown to the user as `※ memory: saved prefers-hinglish-short-replies`.

**Migration:** existing `facts` rows → one note each (`type: user`, body =
value, description = `key: value`). `facts` table kept read-only for one
release, then dropped.

### L2 — Session context (`openbro/memory/compaction.py`)

Replaces `Agent._trim_history` and is reused by
`FallbackProvider._fit_to_fallback_context`.

**Budget:** `min(provider.context_window(), memory.max_context_tokens)`.
`max_context_tokens` defaults to 24K because Groq's free tier is TPM-bound,
not window-bound. Add `LLMProvider.context_window()` (base default 32K;
local reads `n_ctx`).

**Token estimate:** `chars / 4` (current heuristic); `tiktoken` if installed.

**Turn boundaries:** a *turn* starts at a `user` message and runs to the next
`user` message. Cuts happen only at turn starts, so tool-call pairs stay
intact by construction. Helper: `split_turns(history) -> list[list[Message]]`.

**Pipeline, run before every LLM call when usage > 75% of budget:**
1. **Clear old tool output** (cheap, no LLM): in turns older than the last 3,
   replace `tool` message content > 1K chars with
   `[tool output cleared — 12.4K chars from file_ops.read]`.
2. If still over: **summarise** all turns except the last `keep_recent_turns`
   (default 6) with one no-tools LLM call, max 800 tokens, fixed sections:
   `Goal · Done · Decisions · Open items · Key facts/paths`.
   An earlier summary is passed in and merged (rolling summary).
3. Result: `[system] + [system: [CONVERSATION_SUMMARY] …] + recent turns`.
4. If the summary call fails: deterministic fallback (list of user requests,
   truncated) — still turn-safe, never crashes the turn.
5. Last resort, if a single turn alone exceeds the budget: keep its first
   `user` message + the newest complete tool pairs.

Emits `bus.emit("system", "context compacted: 38K → 9K tokens")`.
REPL: `/compact [focus text]` forces it; `/context` shows the token breakdown
(system / memories / summary / turns).

`session_memory` goals feed into the summary's `Goal` section; the summary
text is stored on the session row (L3) so resume starts from it.

### L3 — Transcripts (`openbro/memory/transcript.py`, evolves `store.py`)

- `conversations` gains `tool_calls TEXT` (JSON) and `tool_call_id TEXT`; tool
  messages are persisted too, so resume is lossless.
- `sessions.metadata` holds `{"summary": ..., "summary_upto_id": ...}`.
- `--resume`: load summary + messages after `summary_upto_id` → compactor
  makes it fit.
- FTS5 `conversations_fts(content)` powers `memory.search` over past chats
  ("pichhle hafte Excel wali baat").
- One connection per `TranscriptStore` instance, `init_db` once (today every
  call reopens + re-inits).
- Retention: `memory.transcript_retention_days` (default 0 = keep forever).

### Facade (`openbro/memory/manager.py`)

```python
class MemoryManager:
    def system_block(self, user_msg: str, cwd: Path) -> str   # L0 + L1 (+ summary)
    def record(self, msg: Message) -> None                    # L3
    def fit(self, history, provider, tools) -> list[Message]  # L2
    def compact(self, history, provider, focus=None) -> list[Message]
    def resume(self, session_id) -> list[Message]
    def end_session(self, provider) -> list[str]              # auto-extract
    notes: NoteStore; transcripts: TranscriptStore
```

The agent calls `system_block` in `_build_system_prompt`, `record` wherever it
appends to `self.history`, and `fit` right before `provider.chat`. The Telegram
bot keeps one `MemoryManager` per chat user (as now), so notes are per
`user_id`.

## 4. Config

```yaml
memory:
  max_context_tokens: 24000
  compaction:
    trigger_ratio: 0.75
    keep_recent_turns: 6
    clear_tool_output_after_turns: 3
    summary_max_tokens: 800
  index_budget_tokens: 1500
  instructions_budget_tokens: 4000
  auto_extract: auto                # auto | on | off  (auto = off for local)
  embeddings: auto                  # use sentence-transformers if installed
  transcript_retention_days: 0
```

`agent.max_history` is deprecated (ignored with a warning).

## 5. What gets removed

- `MemoryManager._working` deque and `working()/clear_working()`.
- `core/reasoning.py` (unused) — `brain/reflection.py` stays dormant until a
  follow-up decides whether skill-confidence learning comes back.
- `brain/memory.py` as a separate DB: its embedding helpers move into
  `notes.py` as the optional ranker; the old `brain` memory DB is left on disk
  untouched.

## 6. Rollout

| Phase | Scope | Fixes |
|---|---|---|
| **P1** | `compaction.py`: `split_turns`, tool-output clearing, LLM summary, `/compact`, `/context`; replace `_trim_history`; reuse in `FallbackProvider` | orphan-tool 400s, context loss |
| **P2** | `notes.py` + FTS5, memory tool v2, ranked index injection, "when to save" principle, `facts` migration | 20-fact cap, flat facts |
| **P3** | `instructions.py` (`OPENBRO.md`), `/memory edit` | no human-written instructions |
| **P4** | Transcripts with tool calls, FTS over chats, summary-based resume, single connection | lossy resume, slow search |
| **P5** | Auto-extract on session end, embeddings ranker, delete dead code | memory only on explicit "yaad rakh" |

Each phase ships with tests (`tests/test_compaction.py`, `test_notes.py`,
`test_instructions.py`, extend `test_memory.py`) and passes
`ruff check` + `ruff format`.

## 7. Open questions

1. Notes location: `<storage>/memory/notes/` (follows the custom-drive setting)
   or `~/.openbro/notes/` (easy to find/edit)? Proposed: storage dir, with
   `/memory open` to reveal it.
2. Should auto-extract ask before saving or just
   announce? Proposed: announce, `/memory undo` reverts the last batch.
3. Telegram: should memories be shared between the CLI user and their
   Telegram identity? Needs a user-linking step; out of scope for v2.
